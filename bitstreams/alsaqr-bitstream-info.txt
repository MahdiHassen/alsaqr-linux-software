alsaqr_xilinx_48.bit: 38k UART (hardwired), 10Mhz, 1MB DSPM- LINUX BOOTED
(NEWEST) alsaqr_xilinx_may18.bit: EVUs KINDA fixed
alsaqr_opendram2.bit: OpenDRAM v5 as DDR4 controller, 38400 UART (hardwired), APMU grant fix (he-soc commit e602d924). LINUX BOOTED (BusyBox shell, clean 38400 console) + March C- full-DRAM test 0 errors.
   CLK: same build recipe as every bitstream -- SoC/RTL is 20 MHz. The 10 MHz lives in the DEVICE TREE (RTL-bug workaround); that DT value is what xilinx_48's "10Mhz" above refers to. Boot does not actually depend on it.
   NOTE: REPROGRAM the FPGA right before booting Linux. A baremetal test (march/load.sh) run first leaves dirty lines in the write-back LLC, and JTAG DTB writes bypass the cache, so the DTB at 0x81800000 gets clobbered -> kernel panic "No DTB passed to the kernel" -> dead-silent boot. Fresh flash = clean boot. (See RUNBOOK.md)
alsaqr_xilinx_x16OpenDRAM.bit: Same as alsaqr_opendram2.bit, except the OpenDRAM controller is now built with x16 timing constraints (larger memory latency -- the CPU waits more clk cycles per access; this extra latency is the expected/designed behaviour, not a bug). Still 20 MHz SoC, 38400 UART (hardwired). LINUX BOOTED (BusyBox shell). Same REPROGRAM-before-boot rule applies.

Same REPROGRAM-before-boot rule applies.alsaqr_xilinx_50MHz.bit: he-soc commit 8a42dbac (2026-09-16) "Fix miss_handler latch; VCU118 flow at 50 MHz". 4 cores, stock Xilinx DDR4 (MIG), SoC clock 50 MHz, UART hardwired 38400 (DLL 0x51). Host AXI xbar and CCU LatencyMode CUT_ALL_PORTS (a few more cycles per LLC access than the 20 MHz builds; 2.2x faster in wall time). Verified 2026-09-18: apmu-software evu_test PASS, mempol (902 pause/resume IRQs), sad_profile (8 padarray4 calls per pass, with the word-copy firmware loader; see apmu-software README). Cycle counts are not comparable with the OpenDRAM bitstreams (different DRAM controller and interconnect pipelining).

WNS 0.0, hold -0.315 only on the known adv_timer paths.
