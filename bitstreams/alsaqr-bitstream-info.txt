alsaqr_xilinx_48.bit: 38k UART (hardwired), 10Mhz, 1MB DSPM- LINUX BOOTED
(NEWEST) alsaqr_xilinx_may18.bit: EVUs KINDA fixed
alsaqr_opendram2.bit: OpenDRAM v5 as DDR4 controller, 38400 UART (hardwired), APMU grant fix (he-soc commit e602d924). LINUX BOOTED (BusyBox shell, clean 38400 console) + March C- full-DRAM test 0 errors.
   CLK: same build recipe as every bitstream -- SoC/RTL is 20 MHz. The 10 MHz lives in the DEVICE TREE (RTL-bug workaround); that DT value is what xilinx_48's "10Mhz" above refers to. Boot does not actually depend on it.
   NOTE: REPROGRAM the FPGA right before booting Linux. A baremetal test (march/load.sh) run first leaves dirty lines in the write-back LLC, and JTAG DTB writes bypass the cache, so the DTB at 0x81800000 gets clobbered -> kernel panic "No DTB passed to the kernel" -> dead-silent boot. Fresh flash = clean boot. (See RUNBOOK.md)
alsaqr_xilinx_x16OpenDRAM.bit: Same as alsaqr_opendram2.bit, except the OpenDRAM controller is now built with x16 timing constraints (larger memory latency -- the CPU waits more clk cycles per access; this extra latency is the expected/designed behaviour, not a bug). Still 20 MHz SoC, 38400 UART (hardwired). LINUX BOOTED (BusyBox shell). Same REPROGRAM-before-boot rule applies.

Cycle counts are not comparable with the OpenDRAM bitstreams (different DRAM controller and interconnect pipelining).

alsaqr_xilinx_ethernet.bit: he-soc main c5d2c1cc (2026-10-18, branch ethernet merged; built 2026-10-17 from 0b302e43). Same as alsaqr_xilinx_50MHz plus the AMD AXI 1G Ethernet subsystem (SGMII to the on-board DP83867, 0x3000_0000) and AXI DMA (0x3004_0000, PLIC 11/15) on the CCU's DMA port (coherent with the cores' caches), the accelerator socket with its coherent DMA port, QoS/CBQRI, DRAM timing shim. 4 cores, stock Xilinx DDR4 (MIG), SoC 50 MHz, UART hardwired 38400. WNS 0.0, hold -0.315 only on the known adv_timer paths. LINUX BOOTS OVER ETHERNET: cable the VCU118's RJ45 to a USB adapter of the PC (PC 10.42.0.1/24, board 10.42.0.2), alsaqr-mcp `linux_boot netboot=true` or by hand he-soc software/netboot + alsaqr-mcp/scripts/netboot_server.py: 19.5 MB payload in 25 s, BusyBox shell 94 s after the loader is released, 4 CPUs, eth0 up at 1 Gb/s, ping/TFTP/TCP both ways. Needs the Linux of this bundle commit ec4410a5 (cva6-sdk/install64: 25 MHz timebase, console 115200, cpus enabled, S45eth static address). JTAG boot (linux_boot) still works too (2 CPUs). Verified 2026-10-18: t_eth PASS 37 on the board, eval B3_linux_netboot 4/4.

(NEWEST) alsaqr_opendram_ethernet.bit: OpenDRAM in place of the MIG's own memory controller, otherwise the same as alsaqr_xilinx_ethernet.bit (4 cores, SoC 50 MHz, AXI 1G Ethernet + DMA, UART hardwired 38400, Linux over Ethernet the same way). Built 2026-10-22 with Vivado 2024.2 from he-soc branch es/opendram-2024.2 at 08706a3d, with OpenDRAM 663ea1e (the unpipelined controller with both refresh fixes: tRFC pad 20 and fix B). On that branch OpenDRAM lives in hardware/ip_list/opendram (moved in 7dcdea04; same design). 08706a3d also fixes constraints.xdc: on main, the axi_cdc<->MIG AXI paths are never timed. Here they are timed and met (setup +0.221 / +0.325 ns). Timing: setup met everywhere. The hold misses are only the known adv_timer paths plus 7 reset-removal checks (-0.031 to -0.053 ns) inside the unused SPI master 1 (i_spim_gen[1]). Linux 6.1.183 needs alsaqr-software 0166940b (linux_patch_6.1, the vDSO clock_gettime fix); without it SSH/scp sessions drop now and then, on any bitstream. Verified 2026-10-23 on this file: Linux netboot (shell in about 90 s), 20/20 16 MiB scp uploads. Verified 2026-10-22 on the same RTL built before the constraint fix (e42d2051): he-soc bare-metal suite 12/12, March C- 4 h (84 passes over 123 MB, 0 errors), retention (24 min with only refresh running, 0 bit flips over 379 MB), memtester under Linux (4 x 64 MB fast + 4 x 2 MB all tests) 0 failures. sha256 56d7fb4268d83069371ba763183fcce8ab0e816eed5e87e972789e6dc66774a9.

alsaqr_opendram_ethernet_16x.bit: alsaqr_opendram_ethernet.bit with OpenDRAM's DRAM timing constraints made 16x longer, a deliberately slow memory so that interference and slowdown effects become visible (the same change alsaqr_xilinx_x16OpenDRAM.bit had). Built 2026-10-23 with Vivado 2024.2 from he-soc branch es/opendram-2024.2-16x at c2c758d8: time_constraints.vh x16, TIME_WIDTH 4->8 (hardware/ip_list/opendram/README.md explains it). Timing: met and the gate is clean (MIG clock +0.261 ns; axi_cdc<->MIG paths +1.457 / +2.078 ns setup); the hold misses are only the known adv_timer paths. The cores see a dependent cache-missing DRAM read take 163 cycles at 50 MHz (87 on alsaqr_opendram_ethernet.bit) and streams about 1.9x slower. Only OpenDRAM's command spacing is scaled, not CAS latency, the PHY or the SoC's own path. Linux 6.1.183 needs alsaqr-software 0166940b (the vDSO fix). Verified 2026-10-23/24 on this file: he-soc bare-metal suite 12/12 (t_dram's bandwidth check made relative to the memory's speed in he-soc af530f67; the old fixed margin fails at 16x), March C- 4 h (46 passes over 123 MB, 0 errors), retention (24 min with only refresh running, 0 bit flips over 379 MB), Linux netboot and 20/20 16 MiB scp uploads. sha256 686708b455c4fb9be858ff3579e85d4bba35fb8df1d0508630936f2f83e7fa86.

alsaqr_opendram_ethernet_16x_hpm.bit: alsaqr_opendram_ethernet_16x.bit built from he-soc main after the OpenDRAM merge (15cca8d8, 2026-10-24, OPENDRAM=1 through alsaqr-mcp fpga_build env), so it also carries Abdur Rahman's CVA6 HPM/Sscofpmf series (3c3b0fc0..5635178b: mcountinhibit, hpmcounter aliases, counter-enable traps, cycle/instret selectors, overflow interrupt 13).
