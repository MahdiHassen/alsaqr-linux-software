# PMU Counter Verification Test

This test verifies that the PMU (Performance Monitoring Unit) can write to its own counter registers using firmware running on the PMU Ibex core.

## Test Architecture

```
CVA6 Core 0                           PMU Ibex Core
┌─────────────────┐                  ┌──────────────────────┐
│ 1. Load PMU     │                  │                      │
│    firmware to  │───memcpy────────→│  ISPM (0x10427000)   │
│    ISPM & DSPM  │                  │  DSPM (0x10428000)   │
│                 │                  │                      │
│ 2. Start PMU    │                  │  PMU Firmware (C):   │
│    core         │───start─────────→│  - Write 0x11112222  │
│                 │                  │    to all counters   │
│ 3. Poll for     │                  │  - Signal completion │
│    completion   │←──done(101)──────│    to DSPM           │
│                 │                  │                      │
│ 4. Read counter │                  │                      │
│    values       │←──read───────────│  Counter Registers   │
│                 │                  │  (0x10407000+)       │
│ 5. Verify =     │                  │                      │
│    0x11112222   │                  │                      │
│                 │                  │                      │

```

## Building

### Prerequisites

1. **RISC-V toolchains** (both RV32 and RV64):
   - For PMU firmware (RV32IM): LLVM or GCC with RV32 support
   - For CVA6 app (RV64): Standard alsaqr toolchain

2. **Update toolchain paths** in `pmu_firmware/Makefile`:
   ```makefile
   CC = /path/to/clang  # or riscv32-unknown-elf-gcc
   OBJDUMP = /path/to/llvm-objdump
   OBJCOPY = /path/to/llvm-objcopy
   ```

### Build Steps

```bash
cd /home/mhassen/he-soc/software/pmu_counter_verify_test

# Build everything (PMU firmware + CVA6 app)
make

# Or build step-by-step:
make clean
make pmu_firmware           # Build PMU firmware first
make                        # Build CVA6 app with embedded firmware

# Verify build:
make show-pmu-size          # Show PMU firmware sizes
make verify-pmu-symbols     # Verify embedded symbols
```

### Build Output

The build process creates:
1. `pmu_firmware/build/text_section.bin` - PMU code (RV32IM)
2. `pmu_firmware/build/data_rodata_bss.bin` - PMU data
3. `pmu_text.o` - Embedded PMU code in CVA6 binary
4. `pmu_data.o` - Embedded PMU data in CVA6 binary
5. `pmu_test.riscv` - Final CVA6 executable with embedded PMU firmware

## How It Works

### 1. PMU Firmware (C Code)

The PMU firmware (`pmu_firmware/main.c`) runs on the Ibex core and:

```c
// Write test value to all 8 counters
for (uint32_t i = 0; i < 8; i++) {
    write_pmu_counter(i, 0x11112222);
}

// Signal completion to CVA6
WRITE_MEM(DSPM_BASE_ADDR, 101);
```

### 2. CVA6 Application

The CVA6 test (`pmu_test.c`):

1. **Loads PMU firmware**:
   ```c
   // PMU binaries are embedded in CVA6 ELF
   memcpy((void*)ISPM_BASE_ADDR, _binary_text_section_bin_start, text_size);
   memcpy((void*)DSPM_BASE_ADDR, _binary_data_rodata_bss_bin_start, data_size);
   ```

2. **Starts PMU**:
   ```c
   write_32b(PMC_BOOT_ADDR, ISPM_BASE_ADDR);  // Set boot address
   write_32b(PMC_STATUS_ADDR, 0);             // Release from halt
   ```

3. **Polls for completion**:
   ```c
   while (read_32b(PMU_DONE_ADDR) != 101) {
       // Wait for PMU to signal completion
   }
   ```

4. **Verifies counters**:
   ```c
   for (int i = 0; i < 8; i++) {
       uint32_t value = read_32b(COUNTER_BASE_ADDR + i * COUNTER_BUNDLE_SIZE);
       // Should be 0x11112222
   }
   ```

5. **Writes success value**:
   ```c
   write_32b(0x85000000, 0x55555555);
   ```

## Troubleshooting

### Problem: PMU firmware doesn't build

**Solution:** Check toolchain paths in `pmu_firmware/Makefile`. You need LLVM or GCC with RV32IM support.

### Problem: Linker errors about missing symbols

```
undefined reference to `_binary_text_section_bin_start'
```

**Solution:** Run `make verify-pmu-symbols` to check if symbols exist. Make sure `pmu_firmware` target runs before linking.

### Problem: PMU timeout (doesn't signal completion)

**Solution:**
1. Check ISPM/DSPM addresses in `linker.ld` match hardware
2. Verify PMU firmware builds correctly
3. Check PMU_DONE_ADDR is correct (should be 0x10428000)

### Problem: Counter values are wrong

**Solution:**
1. PMU may not have write access to counter registers
2. Check COUNTER_BASE_ADDR (0x10407000)
3. Verify COUNTER_BUNDLE_SIZE (0x1000 = 4KB)
